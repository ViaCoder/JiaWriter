# 提示词分阶段说明

JiaWriter 发给模型的规则都在 `src/writer/prompts/`，到了哪一步才发哪一段，每段只发一次，压缩后补发。输入 `/jw prompts` 可以看到下表和本会话已经发过哪些。

| 阶段 | 什么时候发 | 发什么 | 怎么发 |
|---|---|---|---|
| 常驻 | 每次请求 | 身份、`PROMPT_ADD`、核心规则、skill 索引、工具说明 | 系统提示和工具说明 |
| 日期 | 第一条用户消息，以及日期变化后的第一条 | `[Date: …]` | 消息开头 |
| 开始写作 | 读文体 skill，或第一次 `write`、`edit`；只搜索时不发 | 写作手册 | 工具结果 |
| 确定文体 | 模型读 skill | 该文体的要求 | `read` |
| 检索 | 第一次 `search_web`、`fetch_web` 成功 | 检索手册 | 工具结果 |
| 某种方式 | 该方式第一次成功 | 该方式的规则，搜索 4 种、抓取 5 种 | 工具结果 |
| 记素材 | 第一次 `material_add` | 素材规则 | 工具结果 |
| 检查 | 各检查工具第一次 | 该工具结果的处理方法 | 工具结果 |
| 导出 | 第一次 `export_document` | 导出报告的处理方法 | 工具结果 |
| 回退 | 第一次 `draft_restore` | 回退步骤 | 工具结果 |
| 压缩 | 用量到上下文窗口的 80% | 只总结文件里没有的内容 | 摘要请求 |
| 压缩后 | 压缩之后 | 写作状态；已经开始写作时再发写作手册 | 摘要和消息 |
| 上游内部 | `claude`、`codex` 第一次成功之前，以及主对话接口带不了内置工具时 | 搜索和读取指令 | 内部请求 |

压缩时，主题文件夹就是记忆：稿件路径和字数、素材数量、文体、用户的原话都由程序从磁盘写入摘要，模型只补充已确认的决定、用户偏好和下一步。模型摘要失败时这些内容照样保留。

## 上游搜索进主对话

`claude`、`codex` 方式第一次在单独请求里成功后，上游自带的工具就加进主请求，主模型自己读页面，官方的 Claude Code 和 Codex 也是这样。主请求是 Anthropic Messages 或 OpenAI Responses 接口时才这样做；工具没有实测成功之前不加，因为上游拒绝它会让整个对话失败。

| 接口 | 加进主请求的工具 | 下一轮发回 | 归档里的原文 |
|---|---|---|---|
| Responses | `web_search` | `web_search_call` 记录 | 上游不把页面文字给客户端。模型打开和引用过的页面由服务端再读一次：有 `alpha/search` 就存原文，没有就存服务端的详细报告，并标明“上游转述” |
| Messages | `web_search`（5 次）、`web_fetch`（4 次） | 配对的调用和结果块 | `web_fetch` 的文字直接保存；其余引用的页面用 `claude` 方式读 |

这些记录存成 `serverItem` 块。没有结果的调用不发回。服务端循环到 10 轮会返回 `pause_turn`，程序自动继续，连续最多 3 次。服务端读不到的页面，归档里只有地址，结束时告诉用户。

渠道由用户决定：程序和模型都不会在失败后自动换到别的方式，只说明哪里失败，由用户选下一步。

实测一个 Responses 上游时，页面内容到下一轮就没有了，发回的记录里没有页面文字，所以模型要当场写下要用的内容。

模型自己的函数工具叫 `search_web`、`fetch_web`，把 `web_search`、`web_fetch` 这两个名字留给上游工具，因为工具名不能重复。

## 搜索日志

每次 `search_web`、`fetch_web` 都写日志，用来查搜索为什么失败。`/jw log` 显示文件位置和大小，文件是 `logs/search.log`，超过 5 MB 时移到 `search.log.1`。

| 记录 | 内容 |
|---|---|
| `session` | 程序版本、系统、模型、接口 |
| `turn` | 对话模型这一轮调用了哪些工具，以及停止原因和错误 |
| `tool` | 工具的参数和模型读到的结果 |
| `start`、`done`、`failed` | 一次上游搜索或抓取的开始和结果 |
| `request`、`response` | 发出的字段、请求头名称、HTTP 状态、请求 ID |
| `event`、`stream` | 事件流里每种事件的样例和次数，以及最后一个事件和结束方式 |
| `body` | 上游没有返回事件流时的内容 |
| `attempt-failed` | 某种请求方式失败时 SDK 的原始错误 |

日志里有查询词和上游返回的文字，请求头只记名称，key 和认证信息不写入。网址也不写入：上游地址、页面地址和文字里的网址都换成 `<url>`，请求只记路径最后两段，比如 `/v1/responses`。所以日志能说明第几次抓取为什么失败，说不出是哪个页面。

## 格式

身份是开头的纯文本，`PROMPT_ADD` 紧跟其后。其余分节用 `# 标题` 加 ` - ` 列表，工作目录在 `# Environment` 下。工具说明用第三人称现在时开头，规则多时用 `Usage:` 列表。

## 上游搜索和 Claude 思考块

Claude 的思考块绑定工具集，工具集中途变化会使之前的思考块失效。所以 Claude 的内置工具只在新对话的第一条请求带上：证明成功后写入 `<agentDir>/proven.json`（只存哈希，不存地址），下一个新对话才生效；已开始的对话工具集不变，恢复对话时沿用记录。Codex 仍在证明后立即加入。

## 权限模式

`JW_PERMISSION` 或 `/jw permission` 选择 `manual`、`auto`（默认）或 `bypass`。风险分类是 `writer/permission.ts` 里的固定规则，不由模型判断。

| 动作 | manual | auto | bypass |
|---|---|---|---|
| 只读 | 每个范围首次询问 | 放行 | 放行 |
| 普通动作 | 每次询问 | 每个范围首次询问 | 放行 |
| 高风险 | 每次询问 | 每次询问 | 放行 |

没有人能回答时，询问变成拒绝。任何模式都不往密码框输入。现有的 `bash`、`write`、`edit` 不受影响。

## browser 工具和介入协议

`browser` 操作专用 Chrome 窗口里的页面，按无障碍树的引用行动，覆盖跨站框架和 Shadow DOM。工具集在会话开始时固定：连着扩展才提供，`JW_BROWSER` 可强制。

每个结果都有 `effect`、`route`、`next`、`reason`，`next` 说明谁接着做。

| 情况 | 处理方 |
|---|---|
| 扩展未连接、版本过旧 | 程序提示用户 |
| 引用失效 | 程序按角色和名称重新定位一次，唯一匹配才继续 |
| 动作后页面没变化 | 程序比较后交模型判断 |
| 验证页面 | 用户；该站点本轮不再重试 |
| 密码框 | 任何模式都拒绝 |
| 同一目标失败两次 | 程序熔断，交用户 |

`eval` 一次性运行，默认隔离世界，属于高风险，弹窗显示站点和完整代码。

## 图片兜底

上游可能是任何端点，所以程序不估算费用，只控制张数和尺寸。

顺序：无障碍树 → 本机文字识别（macOS Vision、Windows.Media.Ocr、已安装的 tesseract）→ 把截图发给上游。同一画面第二次 `look` 才会发图，发图属于高风险。

上游是否收图按固定顺序判断：`JW_IMAGE` → 模型声明 → 上次记录（`<agentDir>/vision.json`）→ 模型列表 → 一次极小的探测。探测也计费，所以放在用户同意之后。

默认每轮 1 张、每会话 10 张（`JW_IMAGE_MAX=1,10`），长边 1024（`JW_IMAGE_EDGE`）。`read` 读图走同样的同意和额度。已发的图片留在历史里，因为改写历史会让部分模型丢失推理，压缩时自然清掉。

## computer 工具

操作桌面应用，用固定版本的 cua-driver（稳定版，MIT），不进主包。`/jw computer` 由程序一步步完成下载、校验、系统权限和复查，全程不调用模型；`/jw doctor` 一次检查全部并给出下一步。

各系统用自己的方法：Windows 用 UI Automation，macOS 用 Accessibility，Linux 用 AT-SPI。遥测在每次启动时关闭，驱动看不到密钥。模型只能用固定动作：`windows`、`launch`、`read`、`click`、`type`、`key`、`scroll`、`look`，驱动的其他工具碰不到。

投递一律后台，驱动拒绝时交给用户，程序从不自动抢前台。浏览器窗口只读，终端和 IDE 不打字，密码框一律拒绝。

输入用 `set_value`：`type_text` 在 0.41.2 上会截断中文，所以非 ASCII 文字绝不走按键路线。
