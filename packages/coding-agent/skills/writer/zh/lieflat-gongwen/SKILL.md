# 公文写作

按文种写出像真人起草的公文：观点先行、证据具体、用语克制。程序会检查引用格式、标题编号、段内序号、占位和 AI 腔，这里只写程序管不到的写法。

## 步骤

1. 判文种：摸情况、提建议写调研报告；会上部署写领导讲话；给下级立规矩写工作意见；报做法写经验材料；定目标分任务写工作方案；通知、请示、批复、函等法定公文看 `参考/法定公文样例/` 的版式。
2. 只写一段或一节时，直接写这一部分，不建大纲。
3. 写整篇时，先读 `公文语料/文章结构模板.md` 里对应文种的一节排结构，再把材料里的案例和数据按论点分配，用 material_add 记下每个论点用哪一条。
4. 写完后程序按标题判断文种，自动做公文参数检查，只报硬冲突；照着改即可，不必自己调用 `gongwen_check`。

## 分析段落

现状、问题、风险、趋势这类分析，每个小标题下一般写一个自然段，150–300 字：

1. 段首一两句论点：写清什么导致什么、靠什么机理，以及和全文主题的关系；不写“随着……”的大背景，不写“呈现……特征”的空话，也不写材料里没有的数字和时长。
2. 再用材料佐证：每个论点配一个论证力最强的案例，可另配一项数据。最强指直接证明这个论点而不是旁边的论点、主体和数字具体、时间近、来源权威；讲同一道理的其他事例最多一句话带过。全文每个案例和数据只用一次。
3. 论证多于叙述，约六比四；案例用概括的话交代谁、做了什么、关键数字和结果，不写神态和心理细节。
4. 有第二层意思时用“同时”“此外”引出，同样先论点后材料；能靠内容顺承的不加过渡词。
5. 材料讲完即收段，不写“这说明”“由此可见”这类复述；需要收束时向前推一步，写根源、过程或趋势，落到具体对象上，不写“提出更高要求”“压力加大”“具有重要意义”。

## 对策建议

- 每条对策一个动宾短语的小标题，下面只写一个自然段，不复述前文。
- 段首用“针对”“面向”“围绕”“着眼”“鉴于”之一引出对应的问题，各条轮换；不用“若”“如果”“可能”这类假设语气。
- 段内写几句“要＋具体动作”，每句再用一两句讲清怎么做：渠道、机制、时机、着力点；用“要”不用“应”，不加序号。
- 针对前文问题的根源下药，写能落地的办法，不写“加强、健全……机制”式的口号；核心动词轮换着用。
- 责任主体只在明确时写，用职能泛称（公安机关、市场监管部门）；平台、标准用全称。
- 对策里不举案例，不写日期和出处。

## 法定公文

- 承启句定文种：通知用“现将有关事项通知如下：”，批复、复函用“……收悉。现批复如下：”。
- 批复第一句先表态，理由在后。篇幅按事项定，事情说完就停。
- 结尾：通知“特此通知”，请示“妥否，请批示”，报告“特此报告”，函“特此函复”；调研报告和经验材料自然收束，不加结语。

## 标题

- 篇名写“发文机关＋事由＋文种”或直接说事，不加修辞前缀。
- 小标题平实直陈判断，最多 20 字，不堆“承载能力”“效能”这类抽象名词；一组标题句式一致，方案、意见类一级标题 4–8 字。拟标题时读 `标题技法库.md`。

## 语言

- 句子靠并列成分撑起长度，分析类容易写得太散，方案、意见类容易堆砌；不知道怎么改时读 `句子对照库.md`。
- 论证正面递进，不靠“但”“却”“反而”制造对比；判断词和证据相称，少用“根本无法”“远远超出”这类绝对说法。
- 直呼其名，少用“这类”“该群体”“上述”等指代；自称写“我”“我国”，不写“我方”“中方”“美方”。
- “必须”“应当”“不得”“严禁”一篇不超过两三个；破折号最多一个；冒号只用于引语、主送机关和法定公文的层次标题。
- 术语确实难懂时才在首次出现处加一个简短括注；众所周知的机构直接写名称。
- 批评体制前先写已有成效；经验材料不写本单位尚未解决的问题。
- 事实只用材料里有的；没有数据时靠逻辑把道理讲清楚。
